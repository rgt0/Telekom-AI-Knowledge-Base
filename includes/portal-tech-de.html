Technische Dokumentation – Telekom AI Knowledge Base Portal (DE)

Zielgruppe: Entwickler:innen & Maintainer des statischen Portals.

Ziel: Architektur verstehen, Module sicher erweitern, typische Fehler schnell beheben.

1. Überblick: Was ist dieses Portal?

Das Portal ist eine statische GitHub-Pages-Seite mit clientseitigem Routing (#hash) und dynamischem Nachladen von HTML-Fragmenten aus dem Ordner pages/. Zusätzlich unterstützt es:

  • automatisches Inhaltsverzeichnis (TOC) aus H2/H3,
  • Seiten-internes Highlight-Suchen,
  • globale Suche (Schnell-Index + Volltext).

3. Core-Modul: index.html (Shell)

index.html ist die Shell: Layout, Sidebar, Topbar, Content-Container.

  • Wichtig: id="content" darf genau einmal existieren (Ziel für das Nachladen).
  • Wichtig: id="toc" existiert, damit das TOC gefüllt werden kann.
  • Wichtig: Suchfelder müssen per ID eindeutig sein (z. B. searchBox, globalSearch).

3.1 Script-Reihenfolge

Empfohlene Reihenfolge (damit Basissystem immer stabil bleibt):

<script defer src="./app.js"></script>
<script defer src="./search-inline.js"></script>
<script defer src="./search-global.js"></script>

Prinzip: app.js darf nie vom Suchcode abhängig sein. Suche ist additiv.

4. Core-Modul: app.js (Routing + Load + TOC + Jump)

app.js ist das Herz: es lädt Seiten aus pages/ anhand des Hashes.

4.1 Hash-Routing

  • #home ⇒ ./pages/home.html
  • #portal-tech ⇒ ./pages/portal-tech.html

Wenn kein Hash gesetzt ist, wird standardmäßig #home gesetzt.

4.2 Seiten-Ladefluss (Load Pipeline)

  1. Fetch der Seite: fetch("./pages/${pageKey}.html")
  2. Render in #content
  3. Includes laden (optional, siehe Abschnitt 5)
  4. Active Links markieren (Topbar/Quicklinks)
  5. TOC bauen (H2/H3)
  6. Pending Jump (wenn globale Suche eine Section-Anchor übergibt)

4.3 TOC: H2/H3 → Sidebar

Das TOC wird aus H2 und H3 generiert. Für jeden Heading wird (falls nötig) ein eindeutiges id erstellt.

Best Practice: Nutze klare, kurze H2/H3-Titel, damit TOC und Volltext-Suche gut funktionieren.

4.4 Pending Jump (Abschnitt-Ansprung)

Die globale Suche kann beim Klick sessionStorage setzen:

pendingPage, pendingAnchor, pendingQuery

app.js scrollt nach dem Laden (und nach dem TOC-Bau) zur Section und kann optional die Query an die Highlight-Suche übergeben.

5. Includes: Gemeinsame Fragmente wiederverwenden

Um Inhalte nicht zu duplizieren, werden Fragmente in includes/ gepflegt und per Platzhalter eingebunden:

<div data-include="./includes/portal-guide.html"></div>

5.1 Include-Loader (Empfehlung)

Damit TOC und Volltext-Suche Includes „sehen“, sollte der Include-Loader in der Load-Pipeline vor dem TOC laufen.

Hinweis: Bei Volltext-Suche muss auch search-global.js die Includes beim Indexieren auflösen (siehe Abschnitt 8.3).

6. UI/CSS: Sidebar-Scrolling (nur TOC scrollt)

Das Layout nutzt Flexbox. Header/Search/Quicklinks bleiben fix, nur der TOC-Bereich ist scrollbar.

Kritisch: min-height: 0 in Flex-Containern, sonst funktioniert inneres Scrolling nicht.

7. Modul: search-inline.js (Seiten-internes Highlight)

Diese Suche arbeitet nur im aktuellen #content und markiert Treffer per <mark class="hl">.

7.1 Bedienung

  • Tippen: highlight
  • Enter: nächster Treffer
  • Shift+Enter: vorheriger Treffer
  • Esc: löschen

7.2 Robustheit

Der Code sollte in einem IIFE laufen ((() => { ... })()), um Namenskollisionen zu verhindern.

8. Modul: search-global.js (Globale Suche)

Die globale Suche hat zwei Modi:

  • Schnell: nutzt search-index.json (title/tags/excerpt)
  • Volltext: lädt HTML-Seiten, zerlegt in H2/H3-Sektionen, sucht in Abschnittstexten

8.1 search-index.json pflegen (Schnell-Modus)

Für gute Treffer: DE+HU Tags und Synonyme ergänzen (z. B. Übung + Uebung).

Beispiel:

{
  "page": "german-coaching",
  "file": "./pages/german-coaching.html",
  "title": "German Coaching (DE+HU)",
  "excerpt": "Meeting, Status, Nachfragen, RAG, Governance...",
  "tags": ["meeting","nachfragen","uebug","übung","rag","governance"]
}

8.2 Volltext: Section-Index

Volltext baut einen Abschnitt-Index (H2/H3). Treffer enthalten:

  • Seite (page)
  • Section-Anker (anchor)
  • Section-Titel
  • Snippet

8.3 Includes in Volltext berücksichtigen

Wenn Seiten data-include verwenden, muss der Volltext-Indexer diese Includes beim Parsen nachladen und in den DOM injizieren, sonst findet die Volltext-Suche Inhalte nur in pages/, nicht aus includes/.

9. Debugging & typische Fehler

9.1 Seite bleibt leer

  • Console prüfen: SyntaxError/ReferenceError stoppt die Skriptausführung.
  • Network prüfen: wird pages/home.html geladen?
  • Hash prüfen: ohne Hash muss #home gesetzt werden.

9.2 „Identifier already declared“ / „Unexpected token }“

  • Duplizierte Funktionen/Variablen in globalem Scope.
  • Falsche Klammerung beim Copy/Paste.
  • Entitäten im JS (&lt;, &gt;) – unbedingt entfernen!

9.3 Unicode/Look-alike Zeichen

Copy/Paste aus PDFs kann „ähnliche“ Zeichen erzeugen. Dann findet die Suche einen Begriff nur beim Copy/Paste, nicht beim Tippen. Empfehlung: erst in Plain Text (Notepad/VS Code) einfügen.

10. Erweiterung: neues Modul hinzufügen (Checkliste)

  1. Neue Seite erstellen: pages/neues-modul.html
  2. Topbar-Link ergänzen: #neues-modul (data-page="neues-modul")
  3. H2/H3-Struktur nutzen (TOC + Volltext)
  4. search-index.json ergänzen (Schnell-Modus)
  5. Optional: Inhalte als Include auslagern (includes/)
