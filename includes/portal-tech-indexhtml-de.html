index.html – Aufbau & Rollen (Shell/Template)

DE: index.html ist die Shell (Layout + Navigation + Content-Container). Inhalte kommen dynamisch aus pages/*.html und werden in #content geladen.

1) MAIN-Bereich („rechte Spalte“)

DE: <div class="main"> ist der Container für Topbar + Content. Layout: Sidebar links, Main rechts.

2) TOPBAR („Felső navigáció“)

DE: <header class="topbar"> enthält: Menübutton (mobil), Titel, Hauptnavigation (Topbar-Kategorien).

2.1 Menübutton (Mobil)

DE: Der Button #menuBtn steuert das Sidebar-Overlay (auf schmalen Viewports).

  • aria-controls="sidebar": welcher Bereich gesteuert wird
  • aria-expanded: Zustand (offen/zu) – sollte von JS aktualisiert werden

2.2 Topbar Titel

DE: .topbar__title ist rein visuell („Wo bin ich?“).

3) Top Navigation: Kategorien mit Dropdown (details/summary)

DE: Die Hauptnavigation nutzt <details><summary> – das ist ein nativer Dropdown ohne extra JS.

DE: Jede Kategorie enthält Links auf Hash-Routes (z. B. #rag), damit GitHub Pages keine „echten“ Pfade (404) erwartet.

3.1 Warum href="#..." (Hash Routing)?

  • DE: href="#rag" setzt nur den Hash der URL.
  • DE: app.js reagiert auf hashchange und lädt ./pages/rag.html in #content.
  • DE: Ein Pfad wie /rag würde GitHub Pages als Datei/Ordner interpretieren (→ 404), deshalb vermeiden wir das.

3.2 data-page

DE: data-page="rag" ist für den JS-Status (Active-Link-Markierung). JS setzt z. B. .is-active auf das passende a[data-page].

4) Content-Container (einziges Ziel für dynamische Inhalte)

DE: Dieser Block muss exakt einmal existieren – hier wird HTML aus pages/*.html hineingerendert:

<main class="content" id="content" tabindex="-1" aria-live="polite"></main>
  • id="content": Ziel für document.getElementById("content")
  • tabindex="-1": ermöglicht Fokus-Setzen via JS (A11y)
  • aria-live="polite": Screenreader-Hinweis „Inhalt aktualisiert sich“

5) Kommentierte Beispielstruktur (aus dem Portal)

DE: Auszug (kommentiert):

<!-- MAIN -->
<div class="main">

  <!-- TOPBAR -->
  <header class="topbar" aria-label="Felső navigáció">

    <!-- Mobile menu toggle -->
    <button class="icon-btn" id="menuBtn"
            aria-label="Menü"
            aria-controls="sidebar"
            aria-expanded="false">☰</button>

    <div class="topbar__title">Telekom AI Knowledge Base</div>

    <nav class="topnav" id="topNav" aria-label="Fő navigáció">
      <details class="topnav-dd">
        <summary>Mentoring &amp; Learning</summary>
        <div class="topnav-dd__menu">
          <a href="#de-mentoring" data-page="de-mentoring">DE‑Mentoring — COBOL — AI</a>
          ...
        </div>
      </details>
      ...
    </nav>
  </header>

  <!-- EINZIGER Content Target -->
  <main class="content" id="content" tabindex="-1" aria-live="polite"></main>

</div>

6) Praktische Regeln (damit es stabil bleibt)

  1. DE: #content darf nur einmal vorkommen (sonst lädt JS in das falsche Element).
  2. DE: Interne Links immer als href="#slug" (keine Pfade wie href="portal-tech").
  3. DE: H2/H3 sauber nutzen → TOC + Volltext-Suche funktionieren automatisch.

Fortsetzung: index.html – Sidebar, Suche, Overlay, IDs (DE)

7) Sidebar: Struktur & Verantwortung

DE: Die Sidebar ist (a) Navigation/Tools und (b) dynamisches Inhaltsverzeichnis (TOC) für die aktuell geladene Seite.

7.1 Empfohlene Sidebar-Bausteine

  • Header: Brand + optional GitHub-Link
  • Search (Seitenintern): Highlight-Suche innerhalb von #content
  • Global Search: Suche im gesamten Portal (Schnell/Volltext)
  • TOC (scrollbar): dynamisch aus H2/H3 der aktuellen Seite
  • Quicklinks + Top: feste Links (z. B. Home, RAG, Irányelvek)
  • Footer: Copyright

7.2 Beispiel: Sidebar-HTML (vereinfachter Auszug)

<aside class="sidebar" id="sidebar" aria-label="Oldalsáv">

  <!-- FIX oben: Header/Brand -->
  <div class="sidebar__header">
